# macOS Token 消费统计（1.4.0-preview.1）

左侧「Token 统计」提供今日、近 7 天、近 30 天、全部记录；显示输入、缓存输入、输出、推理、每日趋势和模型分布，可导出每日 CSV。

## 数据口径

- 离线、只读扫描 `CODEX_HOME`（默认 `~/.codex`）中的 `sessions/` 和 `archived_sessions/` JSONL 日志。
- 仅来源明确为 `Codex Desktop` 的主会话。桌面端的 `source` 也可能是 `vscode`，所以使用 `originator` 区分插件。独立 CLI、VS Code 插件、来源未知、分叉/子代理继承历史不计入。
- 这是一份**部分本机可观测统计**，并非所有设备或完整账户账单。临时预热无持久会话日志，未计入。
- 用 `event_msg.token_count.info.total_token_usage` 的累计增量计算；同会话重复通知、归档副本不重复累计。回退/乱序计数跳过并提示可能不完整；没有日期的增量不归入后来日期。
- 总量 = 输入 + 输出。缓存输入是输入的子集；推理是输出的子集。没有这些可选字段时按 0 处理，表示日志未记录该类别。
- 日期按事件时间和系统本地时区分组。近 7/30 天含今天，按日历日计算；与官方滚动额度窗口无关。
- 首个可用累计值归入首个观测时间；日志从中途开始时，其早期用量无法拆分到准确的历史日期。模型按 `turn_context.model`，缺失时显示「未知模型」。
- 不将当前账号或会话创建者当作所有后续请求的账单身份。历史会话可跨账号继续使用，本版不按账号拆分，不显示估算美元费用。

## 隐私与运行

读取统计不启动 Codex CLI、不开网络、不触发额度查询/预热、不读取钥匙串或 auth.json。原有自动预热是独立功能，仍依用户原设置运行。

仅时间、模型和数字进入内存统计；不持久保存消息、工具输出、账号身份或项目路径。CSV 仅日期和计数。关闭应用后内存缓存释放。

首次读取在后台，后续按文件大小/修改时间/inode复用缓存；变化文件重新扫描。本页可见时每分钟刷新，离开页面后不做定时统计。新日志尚未写完的一行等下次读取。日志缺失/来源未知时显示空态，不冒充官方账号 0 消费。

文件流式读取，拒绝符号链接和非本用户的普通文件；单行上限 4 MiB、单文件扫描上限 512 MiB、最多 20,000 文件。超过限额、损坏或读取失败会提示统计可能不完整。

## 验证

`--self-test` 使用虚构日志：累计差分、缓存/推理不重复加总、模型切换、插件/CLI/派生过滤、归档去重、日期边界、夏令时、异常计数、尾行补全、缓存失效、删除、符号链接与只读性。

`--token-scan-test [CODEX_HOME]` 在创建账号模型前运行，只打印数字汇总与耗时，不执行登录、额度查询、自动更新或预热。`--render FILE --tokens [--dark]` 使用虚构界面数据。
