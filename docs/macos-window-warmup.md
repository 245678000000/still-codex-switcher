# macOS 账号预热预览版 · 1.3.1-preview.1

## 本次修复

1.3.0 把「预热一次」错误地限制为重置时间已经过去；刚刷新过额度时还会受到普通刷新冷却影响。现在用户确认后，手动按钮会立即重新查额度并尝试一次，不再要求显示的 5 小时重置时间已经过去。5 小时余额、7 天最低余额与登录状态仍会检查。

自动预热改为：每个账号独立确认；**首次开启后会检查并尝试一次**，此后参考上次记录的重置时间并至少间隔 5 小时，避免每次刷新后新时间覆盖旧时间导致一直等待。开启后后台请求会消耗实际额度。旧版已开启的账号需要重新开启并确认新规则；升级不会悄悄发送请求。

请求完成后显示「预热消息已发送」；这说明模型请求完成，**不等同于证明某个新窗口已经开启**。官方返回的 100% 和未来重置时间也不足以单独证明窗口状态。服务端可能按账号、套餐或时间调整规则。

## 运行边界

- 栖言运行、电脑唤醒时，约每 5 分钟检查；窗口关闭后已开启的账号仍可检查。退出 App 后停止，不添加登录启动项或唤醒设置。
- 5 小时额度须有余额，7 天额度须至少 1%，且服务端返回相应窗口信息；异常时卡片会显示原因。
- 自动请求以预先记录的时间为锚点，按账号串行处理，并保持至少 5 小时的请求间隔；手动请求需再次确认且至少间隔 60 秒。
- 发出模型请求前，在进程间锁内先记录尝试并暂停自动请求。异常退出、超时、网络错误、身份过期或结果不明时保持暂停，避免不确定状态下反复发送。
- 使用 GPT-6 Luna / low；账号模型列表未提供此组合则暂停，不自动换用其他模型。按「停止」结束本轮任务，已发出的请求仍可能产生用量。

## 凭证设计：与临时复制 auth.json 方案的区别

现有额度查询通过官方 app-server 的实验性 `chatgptAuthTokens` 模式使用访问令牌。预热沿用此模式：

1. 当前账号只读当前登录资料；其他账号只读其钥匙串备份，并检查账号 + 工作区身份。
2. 仅通过子进程标准输入传入访问令牌，不传入刷新令牌，不把令牌放进命令行、环境变量或日志。
3. 使用全新的 0700 临时 HOME / CODEX_HOME / SQLite / 缓存目录，临时认证模式，无共享配置、原用户的插件或项目历史；无 API Key、代理服务地址等环境继承。
4. 临时会话不持久保存历史；禁用 shell、apps、多代理、网页搜索等工具，运行采用官方 CLI 的只读沙盒，关闭 shell、执行工具、apps 和多代理，工作目录与配置置于临时目录。只读沙盒不等同于对所有本机文件的读取隔离。遇到额外服务端操作请求即停止。
5. 不刷新、不回写完整登录凭证，避免新功能与桌面端争用刷新令牌。访问令牌过期后请在栖言更新登录备份或重新添加该账号，再手动检查。
6. 所有退出路径清理本次 UUID 目录，日志只显示受控状态，不记录原始服务端报错或模型正文。

**限制：这不是长期免登录的无人值守凭证管理器。** 原有切换功能仍使用登录备份。若以后要自动续期，应另外设计每个账号独立 OAuth 会话和唯一刷新所有者；「复制临时目录再写回」不等同于已经解决多个进程间的刷新竞争。

## 验证范围

本次构建通过 **227 项模拟测试**；另使用系统级断网验证官方 CLI 的模型消息格式。[模拟测试记录](macos-warmup-tests.txt) · [断网协议测试](macos-warmup-turn-tests.txt)。

- 单元、协议、真实子进程、取消/超时及模型层测试均使用虚构账号和临时文件。
- `scripts/macos-warmup-protocol-smoke.py` 在系统层禁止网络，用已安装官方 CLI 检查临时认证、临时会话、只读限制、空的继承指令列表以及令牌未落盘；不发 `turn/start`，不查询额度。
- 经用户明确同意，对一个实际账号完成了一条最小模型请求；此结果不代表验证了所有账号、套餐或窗口机制。实际账号资料和用量未纳入公开仓库。
- 发布安装包和源码，不替换本机已安装 App，也不启用任何真实账号的预热开关。
