# macOS 到期预热预览版 · 1.3.0-preview.1

## 行为与建议

账号卡片增加「到期自动预热」与「预热一次…」。新旧账号均默认关闭，开启和手动运行均有确认框。无需切换当前 Codex 账号，不退出桌面端、不操作 VS Code。

这是一次真实模型用量，不是充值、配额刷新或容量增加。选择 GPT-6 Luna / low；当前账号模型列表未提供此组合则暂停，绝不自动换用其他模型。每次仅发一个 `turn/start`，固定提示「回复ok」。实际消耗取决于服务端；没有承诺固定百分比或免费。

建议先对一个非当前账号手动检查，确认官方额度页的新窗口时间后，再开启该账号的自动预热。

## 调度

- 栖言运行、电脑唤醒时，约每 5 分钟检查；窗口关闭后，已开启且未暂停的账号仍可检查。退出 App 后停止，没有添加 LaunchAgent、cron、登录启动项或唤醒设置。
- 5 小时窗口重置时间已过且再留 60 秒缓冲；7 天余额至少 1%，重置时间仍有效。
- 缺失窗口、查询失败、旧缓存、电脑时间回拨时跳过。先查额度，再在独立子进程里重查一次；若窗口已变化，不发模型请求。
- 自动请求按服务端窗口去重，并设 5 小时最短尝试间隔；手动重试需再次确认且至少间隔 60 秒。
- 账号串行处理。开始前在进程间锁内原子保存窗口和尝试时间；即使 App 异常退出，同一窗口也不会自动重发。
- 请求完成后再次读取额度。只有官方返回未来的新 5 小时重置时间才显示「已确认」。完成但窗口未变化、超时、网络错误、身份过期、取消均暂停自动请求，避免不明结果的重复消耗。
- 按「停止」结束本轮任务。已发出的请求可能仍产生用量，不把取消当作撤销计费。

## 凭证设计：与临时复制 auth.json 方案的区别

现有额度查询通过官方 app-server 的实验性 `chatgptAuthTokens` 模式使用访问令牌。预热沿用此模式：

1. 当前账号只读当前登录资料；其他账号只读其钥匙串备份，并检查账号 + 工作区身份。
2. 仅通过子进程标准输入传入访问令牌，不传入刷新令牌，不把令牌放进命令行、环境变量或日志。
3. 使用全新的 0700 临时 HOME / CODEX_HOME / SQLite / 缓存目录，临时认证模式，无共享配置、原用户的插件或项目历史；无 API Key、代理服务地址等环境继承。
4. 临时会话不持久保存历史；禁用 shell、apps、多代理、网页搜索等工具，运行采用只读沙盒；模型工具的文件读取限于临时目录。遇到额外服务端操作请求即停止。
5. 不刷新、不回写完整登录凭证，避免新功能与桌面端争用刷新令牌。访问令牌过期后请在栖言更新登录备份或重新添加该账号，再手动检查。
6. 所有退出路径清理本次 UUID 目录，日志只显示受控状态，不记录原始服务端报错或模型正文。

**限制：这不是长期免登录的无人值守凭证管理器。** 原有切换功能仍使用登录备份。若以后要自动续期，应另外设计每个账号独立 OAuth 会话和唯一刷新所有者；「复制临时目录再写回」不等同于已经解决多个进程间的刷新竞争。

## 验证范围

本次构建通过 **218 项模拟测试**和 **3 项官方 CLI 离线兼容检查**；[模拟测试记录](macos-warmup-tests.txt) · [离线检查记录](macos-warmup-protocol-tests.txt)。

- 单元、协议、真实子进程、取消/超时及模型层测试均使用虚构账号和临时文件。
- `scripts/macos-warmup-protocol-smoke.py` 在系统层禁止网络，用已安装官方 CLI 检查临时认证、临时会话、只读限制、空的继承指令列表以及令牌未落盘；不发 `turn/start`，不查询额度。
- 实际账号的窗口启动、订阅用量和服务器模型可用性仍需要用户自愿试一次后核验。模拟通过不等于真实账号已激活。
- 发布安装包和源码，不替换本机已安装 App，也不启用任何真实账号的预热开关。
