# macOS 1.7.1-preview.1 本地验收（2026-11-09）

## 已完成

- Apple Silicon 原生优化构建（macOS 14+），ad-hoc 签名及 strict 验签通过。
- `--self-test`：442 项通过，0 失败；使用临时目录、虚构凭据、离线 stdio CLI 和内存钥匙串替身。
- 入口一：后台访问使用禁止授权 UI 的单次查询策略；锁定结果保持独立类型，文件不受影响；手动解锁后自动验证；重复读取短时复用密钥，缓存到期、主动清理后再取钥匙串。
- 入口二：切换显示四阶段；阻塞的 helper 检测、目标读取、回滚保存放到工作线程；回归覆盖启动失败恢复、备份失败不切换、外部并发更新保留、无原文件恢复。
- 入口三：重新登录立即显示验证中，优先中断整轮后台查询；只读额度验证成功显示认证有效，401 显示登录已失效，网络/协议失败显示验证未完成；旧响应不覆盖新凭据，旧 live 文件不借用新保存凭据的绿色状态。
- 渲染检查：浅色完整布局、深色 900×670 紧凑布局、待解锁/验证中/失效/验证未完成/保存新登录未载入卡片。输出为虚构账号。
- 保持现有账号、自动预热、重置卡与导入导出数据格式兼容。

## 边界

- 本轮不使用真实账号重新登录或切换，不发送模型测试消息，不使用真实重置卡；真实重启耗时没有做前后测速。
- 本轮按用户追加要求同步源码至 GitHub；不创建 Release，不上传账号数据、本机日志或安装备份。
- UI 授权行为以离线替身及 native 查询策略检查验收；没有故意锁定用户登录钥匙串或代输系统密码。首次手动解锁或应用签名变化仍可能要求系统授权。
- 新创建 Keychain 项目不增加通用 security 工具信任，已有密钥及 ACL 原样保留。旧 1.7.0 的通用工具权限不是本次自动撤销的范围。
- 安装仅替换栖言应用包并保留原包备份；原有自动刷新/预热设置继续生效。
- 保留 `kSecUseAuthenticationUIFail` 兼容历史文件型 Keychain ACL，当前 SDK 会给出弃用警告；未使用进程全局授权开关。
