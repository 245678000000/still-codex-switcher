# Windows 自动预热（1.3 预览版）

## 使用

- 账号卡片的「自动预热」默认关闭。逐账号确认后开启，首次检查会尝试一条「回复ok」，并非等待截图中显示的未来重置时间才开始。
- 之后至少间隔 5 小时，另留 1 分钟余量，并参考最近成功请求后看到的官方重置时间。每 5 分钟检查；因此不是秒级定时器。
- 「预热一次…」每次弹窗确认并强制更新额度，不受自动开关或未来重置时间阻挡。手动请求间隔至少 60 秒。
- 使用官方模型列表中明确可用的 GPT-6 Luna / low；缺少模型时暂停，不静默替换其他模型。
- 5 小时须有余额，7 天须剩余至少 1% 且有有效重置时间；未知或过期数据跳过。发消息之前还会在独立子进程里复查服务端额度。

**会消耗实际模型额度，也可能涉及账户计费。预热不是补充额度，也不保证启动或延长窗口。** 已在运行的 5 小时窗口不会因这条消息重新计时。完成提示只代表收到服务端 `turn/completed` 且状态为 `completed`，并完成额度复查；不把 100% 显示或重置时间变动当作成功证明。

## 运行与暂停

- 栖言运行且电脑唤醒时生效。最小化后继续检查已开启且未暂停的账号；关闭窗口或退出程序后停止。无独立计划任务、开机任务或常驻后台服务。
- 启用状态、最近尝试、下次时间和固定状态提示保存在账号元数据。更新登录备份保留开关与冷却时间。Windows 旧账号库升级后全部默认关闭。
- 请求之前先将「暂停/处理中」状态落盘；崩溃、网络异常、超时、取消、令牌过期或结果不明后不自动重复发送。
- 发生问题先检查登录备份、网络及官方 CLI，再点击「预热一次…」确认重试；成功后原先开启的自动计划继续。关闭再开启也保留最近尝试的冷却约束。
- 上方「停止」用于取消本次查询/预热。模型请求已经发出时可能已产生用量。关闭自动开关用于停止后续自动尝试。

## 与当前 Codex / VS Code 的关系

预热本身不切换、退出或重启 Codex，也不触碰 VS Code 的登录文件。只启动本工具创建的官方 CLI 子进程，使用独立空目录 `CODEX_HOME`，临时登录只经重定向 stdin 传入选中账号的访问令牌。

当前账号身份匹配时优先读取当前登录文件中的最新访问令牌，否则从该账号的 DPAPI 加密备份读取。无刷新令牌传输，无 `auth.json` 明文临时副本，无凭证回写；过期时提示更新登录备份或重新添加账号。进程结束后清理临时目录；不记录模型输出、原始服务端错误、令牌或私密对话。

整个预热请求持有本工具跨进程操作锁，阻止本工具另一窗口同时切换/移除账号或重复预热。这不是对其他软件的全局锁。

临时会话启用只读沙箱，关闭 shell、联网搜索、apps 和子代理，禁止审批；发现额外工具 item 或服务器请求时终止本次任务。只读沙箱不是对整个主机文件系统的完全隔离承诺。

**账号切换功能的原行为保持不变**：Windows 本机仍使用配置的共享登录目录，本版未新增桌面与 VS Code 登录目录迁移/隔离。自动更新功能也未包含在本版内。

## 测试边界

测试使用虚构账号、临时目录和模拟协议，不登录或消耗真实账号额度。覆盖默认关闭、各账号身份校验、两次额度检查、持久化防重、模型/隔离参数校验、完成事件乱序、令牌过期、冷却、暂停、取消、超时、子进程退出和目录清理。Windows runner 另测 DPAPI/ACL、WPF 开关与浅/深色、小窗口展示。

协议使用本地官方 CLI 0.164.0-alpha.11.1 导出的 schema 交叉检查；`readOnly` 仅发送 `type` 和 `networkAccess`，避免旧的 `access` 参数。真实 Windows 账号的服务端接受情况仍需在该机器上登录后验证。没有把离线验证描述为真实服务端已成功预热。
